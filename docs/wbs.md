# 📋 프로젝트 WBS

※ 이 파일은 Git과 GitHub Projects 연동에 최적화된 마크다운 기반 WBS 문서입니다.
※ 신규 프로젝트(엔터프라이즈 프론트엔드) 구축을 기준으로 작성되었습니다.
※ 세부 작업 목록 끝의 대괄호 `[Must]`, `[Should]`, `[Could]`, `[Won't]`를 기준으로 개별 우선순위(Priority)를 정의합니다.
※ 섹션 번호(01~)는 고정 WBS 코드입니다. 항목을 추가해도 기존 번호는 변경하지 않습니다.
※ 각 항목 본문은 **목적 / 작업 내용 / 완료 조건(AC)** 구조로 작성하며, 이 내용이 GitHub 이슈 본문으로 동기화됩니다.

### 01. 프로젝트 기반 구축
- [ ] 빈 스켈레톤 애플리케이션의 개발(Dev) 서버 빌드 및 최초 배포 검증 (PoC) [Must]
  * **목적**: 코드 작성 전 빌드·배포 파이프라인이 실제로 동작하는지 조기 검증해 인프라 리스크를 선제거
  * **작업 내용**:
    - 빈 앱 빌드 산출물을 타깃 클라우드 인프라(S3 / CloudFront 등)에 배포
    - 배포 도메인 접속 및 정적 자산 서빙 정상 동작 확인
  * **완료 조건(AC)**:
    - 빌드 → 배포 → 브라우저 접속까지 무중단 성공
    - 배포 절차가 문서로 정리되어 재현 가능
- [ ] [협업] SPA 라우팅 대응을 위한 웹서버 Fallback 설정 요청 및 동작 확인 [Must]
  * **목적**: 직접 주소 입력·새로고침 시 404가 나는 SPA 고질 문제를 인프라 설정으로 해결
  * **작업 내용**:
    - Nginx(try_files) 또는 CloudFront(Error Page 403/404 → index.html) 설정을 인프라팀에 요청
    - 배포 후 딥링크 진입 및 새로고침 시나리오 QA
  * **완료 조건(AC)**:
    - 임의 라우트에서 새로고침 시 index.html이 정상(200) 서빙
    - 비정상 404 화면 미노출
- [x] 모노레포 구조 설정 (turborepo + pnpm workspace) [Must]

- [x] 번들러 설정 (Vite, 앱별 포트 분리) [Must]

### 03. 인증
- [x] 로그인 폼 UI (id / password / submit 버튼) [Must]
  * **목적**: 사용자가 자격증명을 입력해 인증을 시작하는 첫 진입 화면 제공
  * **작업 내용**:
    - 아이디·비밀번호 입력 필드 및 제출 버튼 구성
    - 클라이언트 입력 검증(빈 값·형식) 및 인라인 에러 표시
    - 제출 중 버튼 비활성화/로딩 인디케이터 처리
  * **완료 조건(AC)**:
    - 빈 값/형식 오류 시 제출 차단 + 에러 메시지 노출
    - 로그인 성공 시 메인 화면으로 라우팅
- [x] 로그인 API 연동 [Must]
  * **목적**: 입력 자격증명을 서버 인증 API와 연동해 토큰 발급
  * **작업 내용**:
    - 비밀번호 해싱(sha256) 후 전송 정책 적용
    - 로그인 성공 시 토큰 수신 및 저장 연계
  * **완료 조건(AC)**:
    - 정상 자격증명으로 토큰 발급·저장 완료
- [x] 토큰 저장 전략 결정 (localStorage / cookie / sessionStorage) [Must]
  * **목적**: 보안과 사용성(탭 공유·새로고침 유지)을 고려한 저장소 선택
  * **작업 내용**:
    - 탭 간 세션 공유 및 페이지 새로고침 시 유지를 위해 localStorage 사용 정책 수립
  * **완료 조건(AC)**:
    - 새로고침·새 탭에서 로그인 상태 유지 확인
- [x] 로그인 실패 에러 처리 [Must]
  * **목적**: 실패 원인을 사용자에게 명확히 안내
  * **작업 내용**:
    - 비밀번호 불일치, 존재하지 않는 아이디, 계정 잠김 등 에러 코드별 분기
    - 알림 팝업 또는 인라인 에러 텍스트 표출
  * **완료 조건(AC)**:
    - 실패 코드별로 구분된 안내 메시지 노출
- [x] Access token 만료 → silent refresh 처리 [Must]
  * **목적**: 토큰 만료 시 사용자 개입 없이 세션을 자동 연장
  * **작업 내용**:
    - 401 응답 시 refresh 토큰으로 access 토큰 재발급
    - 동시 요청 single-flight 처리 (refresh 1회만 호출)
  * **완료 조건(AC)**:
    - 만료 직후 요청이 재발급 후 자동 재시도되어 성공
    - 동시 다발 요청에도 refresh 중복 호출 없음
- [ ] Refresh token rotation 전략 [Should]
  * **목적**: 탈취 리스크를 줄이는 회전형 리프레시 토큰 정책 적용
  * **작업 내용**:
    - 새로운 Access Token 발급 시 Refresh Token도 동시 갱신(RTR) 정책 정의
    - 재발급 실패 시 기존 잔여 토큰 파기 및 즉시 강제 로그아웃
  * **완료 조건(AC)**:
    - 재발급마다 refresh 토큰 교체 확인
    - 실패 시 토큰 폐기 후 로그아웃 동작
- [x] 로그아웃 처리 [Must]
  * **목적**: 클라이언트·서버 양쪽 세션을 안전하게 종료

  * **완료 조건(AC)**:
    - 로그아웃 후 보호 라우트 접근 불가
    - 잔여 토큰/상태 미존재
- [x] 로그인 상태에 따른 라우팅 제어 (PrivateRoute) [Must]
  * **목적**: 인증 상태에 맞지 않는 페이지 접근을 정리
  * **작업 내용**:
    - 인증된 세션에서 /login 재접속 시 /main으로 역-리다이렉션 처리
