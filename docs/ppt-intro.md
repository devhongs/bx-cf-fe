2p -
03:
고객사별 차이를 흡수해야 함
내용:
금융권 채널 프로젝트는 고객사마다
업무, 인증, MCI, 계정계·정보계·대외계 연동 방식이 다르므로
공통 기반은 표준화하고 차이는 확장 구조로 분리해야 함

3p -
핵심 정의:
Channel Foundation은 채널 프로젝트에서 반복되는
프론트엔드 관리자 UI, 인증, 권한, 게이트웨이, MCI 연동 기반을 표준화한
채널 구축 표준 베이스

보조 문구:
완제품 솔루션이 아니라 프로젝트를 빠르게 시작하기 위한 기반 자산이며,
향후에는 core, mci, full 등 모듈 단위 제공까지 확장하여 납품할 수 있는 구조를 지향함

카드 1:
공통 구조 표준화
프로젝트마다 반복되는 FE/BE 기본 구조와 개발 규칙을 정리해 초기 구축 부담 감소
카드 2:
고객사별 확장 대응
업무와 연동 방식의 차이는 adapter, mapper, config 구조로 분리해 유연하게 반영
카드 3:
모듈형 확장 기반
현재는 구축 베이스로 활용하고, 향후 요구에 따라 core, mci, full 구성으로 확장 가능

4p -
변경해봤자 잘 안읽을거 같고 의미 없을듯

5p -
상단 설명:
1단계는 고객사 업무 로직이 아닌
공통 기반, 실행 구조, 개발 표준, 샘플 흐름 확보에 집중
1개월차:
공통 기반 정리
내용:
FE/BE 모노레포 구조, Gateway, 인증 흐름, 관리자 기본 구조 정리 / 서비스 실행·배포 기준을 검증
산출물:
기본 아키텍처 · 공통 프로젝트 구조 · 실행 스크립트
2개월차:
핵심 모듈 구현
내용:
auth, system, gateway 기반 안정화 / mci-svc의 거래 정의, mapper, adapter routing 구조 구현

3개월차:
검증 및 가이드화
내용:
Admin UI와 Backend API 연계 검증 / 프로젝트 투입 시 활용 가능한 개발 가이드, 샘플 정리
